# PXI growth-surface audit — 6 August 2026

Scope: SEO, share previews (web + app), analytics, Google Ads, Search Console, and the
social/retargeting pipeline across Instagram, TikTok, X and YouTube.

Everything below was measured against a **production build served locally**, not dev mode
and not a guess. Where a number appears, it came from a script in this repo or from a
request I actually made. **Nothing here is deployed.**

---

## 1. The headline finding

The retargeting loop you described — *read a page on the site, then see our ad on
Instagram* — **had no mechanism at all.** This was not a tuning problem or a budget
problem. The site carried Google tags only.

Google Ads can follow someone across the Display network, Search, Gmail and YouTube.
It cannot place an ad in Instagram, Facebook or TikTok. That inventory is sold by Meta
and TikTok and is only addressable from **their own pixels**, which did not exist here.
No Meta Pixel, no TikTok Pixel, no X Pixel, and no Conversions API on any of them.

So the honest answer to "why doesn't PXI do what Chase does" is that Chase has a Meta
Pixel and we did not. That is now built (§4), but it cannot switch on until you mint
three pixel IDs.

## 4. The social pixel layer (built, dormant)

`src/lib/socialPixels.js` + `src/components/analytics/SocialPixels.jsx`.

Design follows the existing Google tag exactly:

- **Fail closed.** No env ID ⇒ that network's script is never injected. No fallback ID
  anywhere — a wrong pixel ID silently trains a stranger's audience.
- **Consent first.** Nothing injects until `isTrackingAllowed()`, the same single gate the
  Google tag obeys: denial-binding in every region, GPC honoured.
- **Injected imperatively in an effect, not as a `<Script>` tag.** A declarative
  `{allowed ? <Script/> : null}` still fires on first paint before consent resolves.
- **One taxonomy.** Call sites never touch `fbq`/`ttq`/`twq`. The fan-out happens inside
  `track()`, so a funnel step cannot exist in GA4 and be missing from Meta.
- **Standard event names only.** A custom name records but gives the delivery algorithm
  nothing to bid toward — the most common reason social retargeting underperforms.
- **No PII.** Advanced Matching is deliberately off.

Pixel cookies (`_fbp`, `_fbc`, `_ttp`, `_tt_enable_cookie`, `personalization_id`,
`muc_ads`) are in `NON_ESSENTIAL_COOKIES`, so withdrawing consent removes what was already
written rather than only stopping future writes.

Verified: **0 pixel requests** with no env IDs set.

### How the "Chase loop" will actually work once switched on

1. Visitor lands on `/features/branded-event-ticketing`. `_fbp` is set (post-consent).
2. `track('view_item')` fires → GA4 gets `view_item`, Meta gets `ViewContent`, TikTok gets
   `ViewContent`.
3. In Meta Ads Manager you build a **Custom Audience**: "people who fired ViewContent in
   the last 30 days but not Purchase". That audience covers Instagram *and* Facebook.
4. Ads served against that audience are the Instagram ad you described.
5. `purchase` fires server-side from the Stripe webhook, so the audience self-cleans.

Step 3 is a console action. Code cannot create audiences.

## 6. Known issues I did NOT change

**The icon mark is 1.52:1 against its own disc.** Measured, not eyeballed. WCAG wants 3:1
for graphical objects. This is why it turns to mush at 16px — it is an *artwork contrast*
problem, and no amount of resampling fixes it. The usual solution is a light mark on the
purple disc at small sizes. You said to leave the circle as is, so I did. Say the word and
it is a 20-minute change.

**Google's search-result thumbnail** is a separate signal from `og:image` and comes from
in-page imagery. No page has an `<img>` wider than 800px, so Google has no large candidate
to promote. Fixing it means adding a large hero image per page — a design change, not a
metadata one.

**There is no Content-Security-Policy on any HTML document.** The policy lives in
`netlify.toml`, whose `[[headers]]` never reach documents served by the Next runtime —
only static assets. `next.config.js headers()` sends X-Frame-Options, HSTS,
Referrer-Policy and Permissions-Policy, but no CSP. So the site is running with **no CSP
at all**. I kept the netlify.toml policy correct (and added the new pixel domains to it)
but it is inert until the delivery is moved into `next.config.js`. Flagging rather than
fixing, since it is a security change with real breakage risk and deserves its own pass.
